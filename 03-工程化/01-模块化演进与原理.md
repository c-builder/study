# 模块化演进与原理

## 学习目标

- 理解 JavaScript 模块化的演进历程
- 掌握 CommonJS 与 ES Module 的差异
- 理解模块加载、循环依赖的处理
- 了解 UMD 与构建工具中的模块打包

## 为什么需要

早期 JS 无模块系统，全局变量污染、依赖混乱。模块化带来：

- **作用域隔离**：每个模块独立作用域
- **依赖明确**：import/require 显式声明
- **复用与发布**：npm 生态的基础

架构师需理解 CJS/ESM 差异，正确配置 Node、构建工具、TypeScript。

## 核心原理

### 1. 演进历程

```mermaid
flowchart LR
    Global[全局 script] --> IIFE[IIFE 立即执行函数]
    IIFE --> CJS[CommonJS Node]
    CJS --> AMD[AMD RequireJS]
    AMD --> ESM[ES Module 标准]
    ESM --> Bundler[Webpack/Vite 打包]
```

### 2. CommonJS（CJS）

Node.js 默认模块系统，**运行时加载**、**同步**。

```javascript
// math.js
module.exports = {
  add: (a, b) => a + b
};
// 或 exports.add = ...

// main.js
const math = require('./math');
console.log(math.add(1, 2));

// 原理：运行时解析路径，同步读文件，执行并缓存
// module.exports 是 exports 的引用
```

**特点：**

- 值拷贝：`require` 得到的是导出值的拷贝（对象除外，引用传递）
- 动态：`require` 可在任意位置、条件执行
- 循环依赖：部分加载，可能拿到未完成的 exports

### 3. ES Module（ESM）

ECMAScript 标准，**编译时静态分析**、**异步加载**（浏览器）。

```javascript
// math.js
export const add = (a, b) => a + b;
export default { add };

// main.js
import math, { add } from './math.js';
// 注意：浏览器需 .js 扩展名或构建工具解析
```

**特点：**

- 静态：`import` 必须在顶层，编译时确定依赖图
- 值引用：导出的是绑定（live binding），原模块修改会反映到 import 方
- Tree Shaking：静态分析可消除未使用导出
- 循环依赖：引擎处理更完善

```javascript
// 动态 import — 运行时加载，返回 Promise
const module = await import('./heavy-module.js');
```

### 4. CJS vs ESM 对比

| 维度 | CommonJS | ES Module |
|------|----------|-----------|
| 加载时机 | 运行时 | 编译时 |
| 输出 | 值拷贝 |  live binding |
| 语法 | require/module.exports | import/export |
| Tree Shaking | 不支持 | 支持 |
| 浏览器 | 需打包 | 原生支持（type=module） |
| Node | 默认 | .mjs 或 "type":"module" |

### 5. 循环依赖

```javascript
// a.js (CJS)
exports.done = false;
const b = require('./b');
exports.done = true;

// b.js (CJS)
const a = require('./a');
console.log(a.done); // false — a 尚未执行完
```

ESM 通过静态分析构建模块图，循环时可能得到 TDZ（暂时性死区）内的绑定。

**最佳实践：** 避免循环依赖，提取公共模块到第三文件。

### 6. UMD 与打包

UMD 兼容 CJS、AMD、全局变量，用于浏览器 script 标签。现代项目通过 Webpack/Vite 打包 ESM/CJS 为浏览器可用的 bundle。

```html
<script type="module">
  import { init } from './app.js';
  init();
</script>
```

## 常见误区与最佳实践

| 误区 | 正确理解 |
|------|---------|
| "Node 只能用 CJS" | Node 支持 ESM，package.json "type":"module" |
| "import 和 require 可混用" | 需注意互操作，ESM 中 require 不可用 |
| "default export 和 export 等价" | default 是单导出，named 可多个 |
| "循环依赖一定报错" | CJS 可能静默拿到未完成 exports |

**最佳实践：**

- 新项目统一 ESM
- 库作者提供 ESM + CJS 双格式（exports 字段）
- 避免深层循环依赖，架构上分层单向依赖

## 小结

- CJS：运行时、同步、值拷贝，Node 传统
- ESM：编译时、静态、live binding、Tree Shaking
- 理解差异才能正确配置构建与 Node
- 循环依赖需在设计阶段避免
